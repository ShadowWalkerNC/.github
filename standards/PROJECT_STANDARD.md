# Project Standard

Owner: ShadowWalkerNC · Version: 1.0.0 · Applies to: explicitly adopted project scope.
Canonical location: `standards/PROJECT_STANDARD.md`.

A project has an owner, purpose, priority, ecosystem, one primary classification/lifecycle and a manifest. Separate target architecture from observed implementation and release acceptance. Evaluate requirements, internal reuse, existing dependencies and SDKs before custom code. A new top-level repository needs an independent lifecycle, release, deployment, audience, security/ownership boundary or product identity.


Meaningful features follow the [requirements workflow](REQUIREMENTS_WORKFLOW.md): product -> technical -> app-flow diagrams -> backend schema/ownership -> implementation plan, with traceable feature IDs and actual acceptance evidence.
