# Working agreements

Owner: ShadowWalkerNC · Version: 1.0.0 · Applies to: explicitly adopted project scope.
Canonical location: `core/WORKING_AGREEMENTS.md`.

Platform instructions and explicit owner direction govern. Adopted guidance
supplies project defaults; it grants no permissions. Read local project
instructions and verify commands and stack before editing. Name the project and
scope; preserve unrelated work and existing conventions. Use one capable agent
unless delegation is authorized and useful.

Classify risk first. Small changes need targeted checks, not a mandatory panel or
written plan. Significant features need traceable acceptance and a bounded plan;
auth, migrations, destructive actions, and deployments need proportionate review
and actual authorization. Never infer a grant from a model decision or document.

Inspect → make the narrow change → verify affected behavior → report evidence.
Keep domain rules behind stable interfaces; reuse existing dependencies. Record
PASS, FAIL, NOT RUN, or BLOCKED honestly. A build does not certify production.
Update only affected docs. Keep durable project facts with the project, not in a
central shared ledger. Use private/local records for machine paths and secrets.

Select standards and playbooks explicitly. Design presets require a named project
and scope. Upgrades are reviewed, pinned changes, never automatic portfolio rollout.
